## Still broken

**4.2 REGRESSED. The card grid jumps 56px per row when the data lands.**
Most user-visible item in this audit. It hits every user on every cold load of
the gallery, which is the first screen after sign-in.

Commit `a6d2bbe` cut the card from four rows to two. It did not touch the
skeleton, and the skeleton's own comment (`PrototypesScreen.vue:215-218`)
still claims a one-for-one match that no longer exists.

Below the picture, the loaded card is `mt-3` + `h-7` + `h-7` = 68px
(`PrototypeCard.vue:209`, `:271`). The placeholder is `mt-3` + `h-10` +
`mt-2` + `h-9` + `h-7` = 124px (`PrototypesScreen.vue:222-227`). The picture
is `aspect-[16/10]` in both, so the whole difference is 56px per card. The
grid is two columns, so the page collapses 56px per row the moment the list
arrives. The user is watching this screen while the agent writes, which is the
exact moment the finding was about.

Fix: cut the placeholder to two blocks, `mt-3 h-7` and `h-7`, and correct the
comment.

**3.17 NOT DONE. Live reload is still unadvertised where it counts.**
Low priority, real. The viewer promises the reload only when the prototype is
empty or fails to build (`runtime/viewer/boot.js:221`, `:229-230`). A user
whose prototype works never learns the tab reloads itself, so they keep
closing and reopening it after each agent turn. Settings does not say it.
`/help` does not say it. One line on Settings, or on the owner bar, closes it.

## Never seen by a human

No verdict is UNVERIFIABLE: for each finding the class is backed by a rule I
read in the shipped CSS or in `frappe-ui` source. But nobody has rendered any
of this. The preview snapshot tool fails, so this whole effort is
source-reading. These are the surfaces a person should open first, and what to
look at.

1. **The viewer status screen** (`/u/<user>/<slug>` for a 0-file prototype,
   and for one with a syntax error). Look at: does the status box centre, does
   the red glyph read as an error and not as decoration, do 5 stacked error
   rows fit without pushing the box sideways.
2. **The viewer owner bar.** Look at: a prototype whose own root is `h-screen`
   or `position: fixed`. `body.sk-chrome` is a flex column
   (`runtime/viewer/viewer.html:61-69`), which handles a normal tree. A
   prototype that sizes itself to the viewport can still overflow by the bar's
   36px.
3. **`/feed` signed out.** It is now the front door for every first-time
   visitor and no human has looked at it. Look at: the hero, the empty state
   with zero public prototypes, and the card grid at 1280px and at 390px.
4. **`/login` and `/help`.** Both are new templates on core's `base.html`.
   Look at: whether core's `website.bundle.css` really ships the Espresso
   custom properties this Frappe version, because every colour in these pages
   is a `var(--…)` that resolves to nothing if it does not.
5. **Focus rings** across the app, and specifically the viewer owner bar link.
   Tab through the top bar, the card action rail, the menu and both dialogs.
6. **Dark mode.** The card is now a PNG per theme
   (`PrototypePreview.vue:58-66`). Look at: a gallery where one prototype has
   only a light capture, so the fallback at `:65` puts a light picture in a
   dark grid.
7. **The card meta line contrast.** `text-xs text-ink-gray-5`
   (`PrototypeCard.vue:272`). The review measured 4.18:1 on the old markup.
   Nobody has re-measured it on this one.
8. **The 190px / 1090px rails.** The classes line up (`App.vue:49`,
   `AppTopBar.vue:110`, `PageHeader` ships `px-3 sm:px-5`, both page bodies
   match), but the measurement was a browser reading and has not been redone.

- **Task 9, mobile.** The `w-40` rail this named is gone with the tabs, so the
  specific defect is MOOT. Nothing else about mobile was done, and `/feed` is
  now a public page that phones will reach first.
- **Frozen username.** Still frozen. The two read-only fields at the old

  `frontend/src`.
- **`/mcp` sets `sid=Guest` cookies.** Unchanged. Nothing in
  `sketch/mcp/http.py` or `sketch/auth.py` strips them.

  the thumbnail pipeline, which runs a real browser on the server
  (`sketch/thumbnails.py`, `sketch/checkd.py`). If checkd is down, every card
  falls back to "The next check draws this" (`PrototypePreview.vue:116-122`).
  That degrades honestly, but the gallery's picture is now an operational
  dependency it did not have at review time.
