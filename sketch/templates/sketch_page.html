{# The shell for every Sketch page that is not the SPA: `/feed`, `/login` and `/help`. `/feed` is the one a signed-out visitor at `/` is sent to (`sketch/www/sketch.py`). It extends `templates/base.html`, not `templates/web.html`. web.html wraps its content in the portal's breadcrumb bar, bootstrap container and sidebar columns (`frappe/templates/web.html:8-53`), and Sketch has none of the three. The navbar and footer blocks are emptied for the same reason: core fills them with the Standard Navbar and Standard Footer web blocks (`frappe/templates/base.html:66-74` and `80-88`), which are furniture from a different design language. Where the tokens come from. `frappe/templates/includes/head.html:9` loads `website.bundle.css`, and that bundle carries the whole Espresso token layer: the `--ink-*`, `--surface-*`, `--outline-*`, `--radius-*` and `--spacing` custom properties (`frappe/public/css/espresso/colors.css`, `radius.css`, `spacing.css`) and every `text--` type-style class (`frappe/public/css/espresso/typography.css`). frappe-ui builds its Tailwind theme from that same token set, so the type and colour on these pages and in the SPA now resolve to one system (problem 8.4). The type classes below are the ones the SPA writes, spelt the same way. What the bundle does not carry is a full Tailwind utility layer. It is JIT-built from frappe's own templates, so `rounded-6`, `grid`, `max-w-*` and every `hover:` variant are missing. Hence the `sk-` classes.
