Help

Connect your agent, and fix a connection that stays quiet

Connect your agent

Settings carries a ready-made block for eight clients. Each one already holds your token.

  1. 1

    Copy the block for your client. Merge the sketch entry into the config file you have. Replace the file and you lose your other MCP servers.

  2. 2

    Restart your client. Most read the config once, at start.

  3. 3

    Ask your agent to list your prototypes. An empty list is a pass: the token was accepted.

It is not working

The client has no Sketch tools

The top-level key is wrong. Every client reads MCP servers from a different one, and the wrong key fails without an error.

The tools work in one project only

Claude Code needs --scope user. Without it, it binds Sketch to the directory you ran the command in. 

claude mcp add --transport http --scope user sketch \
  {{ mcp_url }} \
  --header "Authorization: Bearer <your-token>"

Gemini CLI has the same default. Pass -s user there.

The agent reports an error

Read it. Sketch answers a bad request with JSON that names the mistake and the header to send. There are three.

  • no_credentials. No Authorization header arrived. Your client dropped it, or the token sits in a field it does not send.

  • wrong_auth_scheme. Sketch reads Bearer only. Send Authorization: Bearer <your-token>.

  • invalid_token. The header was right and the token was not. Copy the current one from Settings. A regenerated token breaks every client that holds the old one.

A claude.ai connector cannot work

The custom connector dialog takes a URL only. It sends no Authorization header. Use one of the eight clients on Settings.

Still stuck

Open an issue on the Sketch repository. Name your client and paste the error. Never paste your token.
