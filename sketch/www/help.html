Help

Connect your agent, and fix a connection that stays quiet

Sketch has no editor and no agent panel. Your own agent writes the files over MCP, so all the setup happens in your client, not here.

What Sketch needs from your client

Four facts. Every ready-made block on Settings already holds them.

Endpoint
{{ mcp_url }}
Transport
Streamable HTTP, POST only
Header name
Authorization
Header value
Bearer <your-token>

One user, one token. Anyone who holds it can write your prototypes.

The top-level key is the usual failure

Every client reads MCP servers from a different key. Paste a block under the wrong one and the client starts with no error at all: it simply has no Sketch tools.

VS Code
servers
OpenCode
mcp
Codex
mcp_servers
Cursor, Claude Desktop, Windsurf, Gemini CLI

The other four traps

  • Windsurf names the URL field serverUrl, not url.

  • OpenCode wants "type": "remote", not http. Keep oauth false, or a refused token starts an OAuth flow instead of failing with a message you can read.

  • Claude Desktop, Cursor and Codex mangle a space inside args. Write Authorization:${AUTH_HEADER} with no space after the colon.

  • A JSON block on Settings is a whole file. Merge the sketch entry into the file you already have. Paste the block over it and you lose every other MCP server.

Claude Code: use --scope user

One command adds Sketch to every project on the machine. Settings prints this line with your own token already in it. 

claude mcp add --transport http --scope user sketch \
  {{ mcp_url }} \
  --header "Authorization: Bearer <your-token>"

Without --scope user, Claude Code binds Sketch to the one directory you ran the command in, and the tools vanish in the next project. Check the result with claude mcp list.

Gemini CLI has the same default. Pass -s user there.

Check that it worked

  1. 1

    Restart your client. Most of them read the config file once, at start.

  2. 2

    Ask your agent to list your Sketch prototypes. An empty list is a success: it means the token was accepted.

  3. 3

    Open Settings. It shows "Last agent request" as soon as a good token reaches Sketch. That line is stamped by your agent only, so it is the one honest signal that the connection works.

What the error means

Sketch answers a bad request with JSON, and the JSON names the mistake. Your client may hide it, so here are the three you can hit.

no_credentials

The request carried no Authorization header. The client read your entry but dropped the header, or you put the token in a field the client does not send. Check the header block in your config.

wrong_auth_scheme

The header arrived with the wrong scheme. Sketch reads Bearer only, so Basic, token and a bare token on its own are all refused. Send Authorization: Bearer <your-token>, and do not invent a header name of your own.

invalid_token

The header was right and the token was not. It was regenerated, mistyped, or it belongs to another account. Copy the current token from Settings and paste it into the client again. Regenerating a token breaks every client that holds the old one, so update them all.

claude.ai connectors do not work yet

A claude.ai custom connector takes a URL only. It cannot send the Authorization header Sketch needs. Use Claude Code, Codex, OpenCode, Cursor, VS Code, Claude Desktop, Gemini CLI or Windsurf today.

Keep a prototype open in a tab while you work. It reloads itself as your agent writes, so you do not have to close and reopen it after every turn.

Still stuck

Open an issue on the Sketch repository. Say which client you use and paste the error your agent reported. Never paste your token.
